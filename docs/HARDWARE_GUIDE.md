# M5Stack Cardputer-Adv 硬件避坑与深度调教指南

本文档记录了将 **M5Stack Cardputer-Adv** 打造成顶级离线语音对讲终端过程中的所有关键硬件踩坑记录与底层寄存器调教方案，供社区开发者参考。

---

## 1. 音频子系统调教 (ES8311 DAC + NS4150B 模拟功放)

### 1.1 硬件架构特征
Cardputer-Adv 与旧版 Cardputer（数字功放架构）不同，采用了 **ES8311 低功耗音频 Codec + NS4150B 模拟功放** 的组合：
- **DAC 输出**：ES8311 将 I2S 数字音频转换为模拟差分/单端信号；
- **模拟放大**：NS4150B 模拟功放芯片直接接收模拟音频并放大驱动 1W 板载扬声器。

### 1.2 破音与音量过小的根因分析
在早期固件调试中，经常遇到两个极端问题：
1. **声音微弱如蚊鸣**：原厂或许多 ESPHome 配置将 ES8311 DAC 音量设定在 `0.55`。在 ES8311 芯片寄存器（REG32 DAC Volume）中，`0.75` 才是 **$0\text{ dB}$（不放大也不衰减的满幅标准电平）**。设定为 `0.55` 时，芯片内部直接衰减了 **$-25.5\text{ dB}$**，导致声音极小。
2. **破音刺耳（数字削波）**：为了解决声音小的问题，部分配置尝试在 `voice_assistant:` 中添加 `volume_multiplier: 4.0`（数字信号放大 4 倍 / $+12\text{ dB}$）。由于 DAC 无法处理超出 16-bit/32-bit 范围的溢出数值，数字信号波峰被硬生生切成平头方波，产生了极度严重的数字削波破音。

### 1.3 黄金配置参数
- **移除数字增益倍乘**：保持 `volume_multiplier: 1.0`（纯净数字信号直通）。
- **校准 DAC 基准音量**：将 ES8311 硬件音量基准设为 **`0.75` ($0\text{ dB}$ 黄金标准)**。
- **动态线性可调范围**：允许在 `0.20`（静音小夜灯档）到 `1.00`（高声大喇叭档）之间无级平滑调节，不失真。

## 2. TCA8418 键盘控制器与矩阵映射真值

### 2.1 硬件架构
Cardputer-Adv 放弃了旧版的 GPIO 软件轮询方案，改用 I2C 接口的 **TI TCA8418 键盘控制器**（固定 I2C 地址 `0x34`，中断引脚 `GPIO 11`）。

### 2.2 原厂 Remap 坐标转换公式
Cardputer 物理键盘表面是 **4 行 × 14 列 (56 键)**，而 TCA8418 在内部电气连接上是 **7 行 × 8 列 (56 个交叉点)**。

原厂驱动库中将 TCA8418 原始 `(raw_row, raw_col)` 转换为 Cardputer 物理 `(card_row, card_col)` 的映射算法为：
```cpp
// card_col (0 ~ 13)
uint8_t card_col = raw_row * 2;
if (raw_col > 3) card_col++;

// card_row (0 ~ 3)
uint8_t card_row = (raw_col + 4) % 4;
```

### 2.3 关键按键硬件真值表
通过反推计算与串口实机抓包验证，各常用功能键的真实坐标与 TCA8418 原始 Keycode（`keycode = raw_row * 10 + raw_col + 1`）如下：

| 按键丝印 | 物理位置 | TCA8418 raw_row | TCA8418 raw_col | 真实原始 Keycode | 常见错误配置 |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **`-` (减号)** | Row 0, Col 11 | **5** | **4** | **`55`** | 误填为 `14` |
| **`+` / `=`** | Row 0, Col 12 | **6** | **0** | **`61`** | 误填为 `15` |
| **`[` (左方括号)** | Row 1, Col 11 | **5** | **5** | **`56`** | - |
| **`]` (右方括号)** | Row 1, Col 12 | **6** | **1** | **`62`** | - |
| **`SPACE` (空格)** | Row 3, Col 13 | **6** | **7** | **`68`** | - |
| **`ENTER` (回车)** | Row 2, Col 13 | **6** | **6** | **`67`** | - |
| **`DEL` (删除)** | Row 0, Col 13 | **6** | **4** | **`65`** | - |

> [!CAUTION]
> **切勿将音量键判断放在对讲打断逻辑之后！**  
> 在本项目的状态机架构中，`-`（55）与 `+`（61）拥有**全局最高优先判定权**。无论系统正在播报、录音还是思考，按音量键立刻调节 DAC 硬件电平并弹出 HUD，绝对不会被误判定为打断或启动对讲。

### 2.4 TCA8418 FIFO 弹出寄存器与中断锁死避坑（芯片手册级铁律）
社区常见的第三方 `tca8418_keypad` 驱动存在两个致命的硬件级死锁陷阱，会导致快速按键或松手时整块 56 键键盘永久失灵（误以为整机死机）：
1. **严禁使用 `REG_KEY_EVENT_A + i` 递增地址读取 FIFO**：根据 TI TCA8418 数据手册，`0x04` (`REG_KEY_EVENT_A`) 是 10 级硬件 FIFO 的**唯一栈顶弹出入口**（每读一次 `0x04`，后续事件自动前移至 `0x04`）。若错误开启 `REG_CFG` 的 `AI` 地址自增并读取 `0x04 + i`，第 2 个事件（如按键松手 Release）会被永久遗留在 `0x04` 无法弹出；
2. **严禁在 FIFO 未排空或回调刷屏前执行 `disable_loop()`**：只要 FIFO 内残留哪怕 1 个未读事件，向 `REG_INT_STAT` 写入清除位是无效的，`GPIO11`（开漏低电平有效）将永远保持在 `0V` 低电平，再也无法触发 `FALLING_EDGE` 下降沿中断。
- **本仓库根治方案**：固定设置 `REG_CFG = 0x01`，在微秒内循环只读 `REG_KEY_EVENT_A (0x04)` 抽干全部硬件 FIFO 并清除 `REG_INT_STAT = 0x1F` 后再分发耗时 UI 回调，同时保留 `GPIO11` 实时低电平守护与 `250ms` FIFO 自愈巡检，从物理层面彻底根除键盘锁死。

## 3. ST7789V 屏幕与高频字模库构建

### 3.1 渲染性能优化
ST7789V 135x240 分辨率在 100ms 刷新率下工作。若文本中出现未定义字模的字符，ESPHome 底层会以每秒 10~20 次的高频向串口抛出 `[W][font:209]: Codepoint not found in font`，严重消耗 ESP32-S3 的 CPU 调度周期，导致掉帧和录音卡顿。

### 3.2 1296 个字模全量覆盖
本项目构建了包含 **1296 个高频汉字**的精简字体子集，全面覆盖：
- 现代汉语高频常用字；
- 全屋智能家居词汇（灯、窗帘、空调、门锁、电视、传感器、插座、风扇、厨房、阳台等）；
- UI 系统状态词汇（就绪、待命、扬声器、音量、流光、雷达、离线等）；
- Whisper STT 常见繁体字容错兜底（已、餐、燈、開、關、話等）。
